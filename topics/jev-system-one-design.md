# Topic 설계 — Jev: System One 모델을 눈으로 확인하기

- 대상 독자: LLM의 기본 동작(토큰, 확률, 샘플링)을 아는 사람
- 소스: https://docs.typesafe.ai/concepts/system-one 및 concepts/ 하위 문서
- 페이지 경로(예정): `/experiments/jev-system-one/`
- 원칙: 반응형 미고려. 데스크톱 한 화면 기준. 텍스트는 흑백, warm 팔레트는 시각화 강조에만 사용.

---

## 1. 이 토픽이 말하려는 것

Jev(TypeSafe의 System One 모델)는 "텍스트를 생성하는 AI"가 아니라 **"타입이 정해진 판단을 돌려주는 AI"**다.
LLM을 아는 사람에게 흥미로운 지점은 정확히 세 가지다.

1. **출력 계약이 다르다** — 자유 텍스트가 아니라, 내가 미리 정의한 답 공간(선택지/레벨/예-아니오) 위의 **확률 분포**가 돌아온다.
2. **보정(calibration)이 학습 목표다** — RLHF(사람이 좋아하는 답) 대신 RLCD(맞을 확률과 일치하는 확률)로 학습한다. "0.9라고 말하면 실제로 10번 중 9번 맞는다"가 모델의 품질 척도.
3. **불확실성이 API의 1급 시민이다** — 분포의 모양에서 `confidence`가 나오고, 코드가 그 값으로 자동 처리/재확인/사람 에스컬레이션을 분기한다.

스토리의 뼈대: **"생성을 포기하면 무엇을 얻는가?" → 구조, 확률, 그리고 신뢰할 수 있는 분기.**

이 세 가지는 전부 "분포"라는 하나의 시각 언어로 표현할 수 있다. 그래서 이 페이지는 처음부터 끝까지 **확률 막대(분포)가 주인공**인 단일 시각 모티프로 진행한다. Seeing Theory가 모든 장을 "표본이 쌓이는 애니메이션"으로 관통한 것과 같은 방식.

## 2. 스토리텔링 구조 (스크롤 = 서사, 각 장에 인터랙션 1개)

세로로 이어지는 5개 장(Act). 각 장은 "짧은 텍스트 + 조작 가능한 시각화 1개"로 구성한다.
인터랙션은 장마다 정확히 하나만 둔다 — 조작할 것이 하나면 배우는 것도 하나.

### Act 1 — 같은 입력, 다른 계약 (도입 훅)

**메시지**: LLM은 문장을 돌려주고, System One은 분포를 돌려준다.

**시각화**: 화면을 좌우로 나눈다. 왼쪽 "LLM", 오른쪽 "Jev".
동일한 고객 문의(“My flight was cancelled. Can I get a refund?”)가 가운데에서 양쪽으로 흘러 들어간다.

- 왼쪽: 타자기처럼 자유 텍스트가 생성됨 (한 글자씩, 매번 조금씩 다른 문장)
- 오른쪽: `refund_requested: 0.95` 같은 typed 답이 **막대 하나가 차오르는 애니메이션**으로 나타남

**인터랙션**: "다시 보내기" 버튼 하나. 누를 때마다 왼쪽 문장은 매번 달라지지만 오른쪽 막대는 거의 같은 자리에 멈춘다. → *반복 실행으로 "구조적 출력의 안정성"을 몸으로 느끼게 하는 장치.*

### Act 2 — 세 가지 질문 도구 (Choice / Score / Noul)

**메시지**: 답 공간은 내가 정의한다. 모델은 그 위의 분포만 돌려준다.

**시각화**: 고객 문의 텍스트 하나를 상단에 고정하고, 아래에 세 개의 카드.

| 카드 | 질문 | 시각 표현 |
|---|---|---|
| Choice | 어느 팀이 처리? | 옵션별 가로 막대 (billing / technical / account) |
| Score | 얼마나 화났나? | 레벨 눈금 위에 놓인 마커 + 레벨별 분포 (`score: 1.4`처럼 레벨 사이에 떨어지는 것이 포인트) |
| Noul | 환불 요청인가? | 0→1 게이지 하나 |

**인터랙션**: 상단 문의 텍스트를 **미리 준비된 4~5개 문장 중에서 선택**(자유 입력 아님 — 실제 API 없이 사전 계산된 분포를 재생). 문장을 바꾸면 세 카드의 분포가 동시에 트랜지션된다. → *같은 state에 여러 질문이 병렬로 붙는다는 감각.*

### Act 3 — 보정이라는 약속 (이 토픽의 심장)

**메시지**: "0.7이라고 말하면 실제로 70%쯤 맞는다"는 것이 RLCD의 학습 목표다. 단, 보정은 집단의 성질이지 개별 답의 보증이 아니다.

**시각화**: 보정 곡선(calibration plot)을 **입자 애니메이션으로 채운다**.
가상의 예측 200개가 공처럼 쏟아져 내려와, 모델이 말한 확률(x축) 구간별 버킷에 쌓인다. 각 공은 실제 정답 여부에 따라 검정(정답)/윤곽선(오답)이고, 버킷마다 검정 비율이 y값이 되어 점이 찍힌다. 잘 보정된 모델이면 점들이 대각선에 붙는다.

**인터랙션**: 슬라이더 하나 — **"과신(overconfidence) 정도"**. 오른쪽으로 밀면 같은 공들이 재분류되며 곡선이 대각선 아래로 휘어진다(0.9라고 말했는데 60%만 맞는 모델). → *RLHF 챗봇의 "자신만만한 헛소리"와 RLCD의 차이를 곡선의 휘어짐 하나로 보여준다.*

이 장이 페이지의 클라이맥스다. Seeing Theory의 "동전을 100번 던져 이론과 경험이 수렴하는" 장면과 같은 역할.

### Act 4 — 분포의 모양이 confidence다

**메시지**: `confidence`는 별도의 마법이 아니라 분포 모양의 요약값이다.

**시각화**: Choice 분포 막대 3개와 그 옆의 confidence 게이지.

**인터랙션**: 막대 자체를 **직접 드래그**해서 분포를 만들게 한다(합이 1로 자동 정규화). 한 막대에 몰수록 게이지가 올라가고, 고르게 펼수록 내려간다. → *NYT "You Draw It"처럼 사용자가 손으로 만든 형태가 곧 개념 정의가 되는 인터랙션.*

### Act 5 — 코드가 분기한다 (마무리, 실전 연결)

**메시지**: 확률과 confidence는 감상용이 아니다. 코드가 그 값으로 행동을 나눈다.

**시각화**: 티켓들이 위에서 아래로 흐르는 파이프라인. 중간에 confidence 게이트가 있고, 게이트를 지나며 세 갈래로 갈라진다 — 자동 처리(오른쪽) / 사용자 재확인(가운데) / 사람 검토(왼쪽). 티켓 하나하나가 warm 컬러 점으로 흘러간다.

**인터랙션**: 게이트의 **임계값 슬라이더 2개**(하한 0.5, 상한 0.9 기본). 움직이면 흐르던 점들의 갈림 비율이 실시간으로 바뀌고, 각 경로 끝의 카운터가 갱신된다. "고위험 작업" 토글을 켜면 상한선이 자동으로 올라가는 프리셋도 하나. → *docs의 "thresholds scale with risk"를 조작 가능한 형태로 번역.*

### (에필로그) 한 줄 요약 + 다음 토픽 연결

"생성 대신 판단, 문장 대신 분포, 프롬프트 엔지니어링 대신 임계값 설계."
Model Routing 토픽(02)과 자연스럽게 연결 — Jev의 use case 중 하나가 바로 LLM 라우터다.

## 3. 문서 내용 중 다루지 않을 것 (범위 제한)

- State 구조화 방법(JSON 경로 참조, 백틱 문법) — 텍스트로 한 줄 언급만
- SDK/HTTP API 사용법, 요금, 모델 목록 — 링크만
- Speculative fan-out, Composite scoring 등 패턴 — Act 5 끝에 "더 보기" 링크로만
- 실제 API 호출 — **전부 사전 계산/시뮬레이션 데이터로 구동** (개인 학습 사이트에 키/비용/네트워크 의존을 넣지 않는다)

## 4. 구현 메모

- 아키텍처: `docs/ARCHITECTURE.md`의 state/model/view/interaction 분리 준수
- 렌더링: 분포 막대·보정 곡선 = SVG + D3, Act 3의 공 낙하와 Act 5의 티켓 흐름 = Canvas
- 데이터: `experiments/jev-system-one/data.js`에 문장별 사전 계산 분포를 상수로 보관
- 애니메이션 톤: 페이지 전체에서 트랜지션 이징/시간을 통일 (`--ease`, 450~600ms)
- 컬러: 분포 막대는 검정, 선택된 답/흐르는 입자에만 warm 팔레트 (amber, magenta)
- 페이지는 길지만 장별 시각화는 뷰포트 진입 시에만 구동 (IntersectionObserver)
