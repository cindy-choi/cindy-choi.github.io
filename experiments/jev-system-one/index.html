System One

같은 입력, 다른 계약

같은 문의에 서로 다른 출력 계약을 적용한 예시입니다. 왼쪽은 생성 문장, 오른쪽은 미리 정한 yes/no 질문의 확률입니다. 실제 Jev API 측정값이 아니라 계약 차이를 보여주는 데모입니다.

State

      
State — 판단의 재료가 되는 컨텍스트

      

        State는 판단할 자료입니다. 문자열·객체·배열을 직접 전달할 수 있고,
        같은 state의 각 질문은 서로 독립적으로 평가됩니다.
        아래 타임라인에 이벤트를 하나씩 추가해 보세요. state가 자랄 때마다
        같은 질문(환불을 요청하고 있는가?)의 분포가 다시 계산됩니다.
      

      

        이 데모에서는 앱이 새 state를 만들어 타임라인을 확장하고 같은 질문을
        다시 평가합니다. 자동 누적 메모리를 API가 관리한다는 뜻은 아닙니다.
      

    


    

      

      

        

        

        
      

    

  


  

    state가 준비되었으니 이제 질문을 던질 차례입니다.
    Jev에서 질문은 자유 텍스트가 아니라 세 가지 타입 중 하나로 선언합니다.
  


  
  

    

      
Primitives (Questions)

      
Choice · Score · Noul — 세 가지 질문 타입

      

        답 공간은 내가 정의합니다 — Choice는 유한한 선택지 위의 분포,
        Score는 순서 있는 눈금 위의 분포(기대값을 낼 수 있습니다),
        Noul은 예/아니오의 단일 확률(임계값과 가장 직결됩니다).
        문의를 바꿔 보세요 — 하나의 state에 세 질문이 병렬로 답합니다. 아래 값은 사전 계산된 예시입니다.

Noul

        
환불을 요청하고 있는가?

        

        

        

          Noul은 boolean이 아닙니다 — 답이 아니라 P(yes)라는 확률 하나를 돌려줍니다.
          그래서 별도의 confidence 필드가 없습니다(값 자체가 확신의 표현).
          0.5는 "중간 정도"가 아니라 yes/no 어느 쪽도 비슷한 확률이라는 뜻입니다.
        

        

      


    

  


  

    "모호한 문의"에서는 분포가 퍼집니다. 이 모양을 요약한 값이 confidence입니다.
  


  
  

    

      
Confidence

      
confidence는 분포의 모양이다

      

        confidence는 별도의 마법이 아니라 확률 분포의 요약값입니다.
        아래 막대를 직접 드래그해서 분포를 만들어 보세요 — 합은 항상 1로 유지됩니다.
        한 옵션에 몰수록 게이지가 오르고, 고르게 펼수록 내려갑니다.
        여기의 정규화 엔트로피는 교육용 지표이며 공식 SDK 수식이라고 주장하지 않습니다.
      

    


    

      

      

    


    

    

  


  

    하지만 이 숫자들은 믿을 수 있을 때만 의미가 있습니다.
    확률을 실제 빈도와 맞추는 것이 calibration입니다. 이는 단일 답의 정답을 보장하는
    속성이 아니라 여러 예측 집단에서 평가되는 성질입니다. Jev가 지향하는
    RLCD(Reinforcement learning for calibrated decisions)는 보정된 의사결정을 학습합니다.
  


  
  

    

      
Calibration

      
0.9라고 말하면, 정말 90%나 맞을까

      

        예측 200개가 쏟아집니다 — 각 공은 하나의 예측이고, 모델이 말한 확률 구간별로 쌓입니다.
        칠해진 공이 정답. 버킷의 정답 비율이 곡선의 점이 됩니다.
        슬라이더로 모델을 과신하게 만들면 곡선이 대각선에서 떨어져 나갑니다.
        이 곡선을 대각선에 가깝게 만드는 것이 보정된 의사결정을 위한 학습 신호입니다.

Advanced: Structure

      
Structure — 질문을 조합해 객체를 만든다

      

        Structure는 독립 SDK 타입이 아니라, 여러 질문을 묶고 응답을 앱 객체로 조합하는 패턴입니다.
        각 필드가 하나의 질문(Choice / Score / Noul)이고, 모델이 필드별 분포를 돌려주면
        그 답들을 앱이 객체로 조립합니다. Choice와 Score에는 confidence가 있고, Noul은 noul 확률만
        돌려줍니다. boolean 변환은 애플리케이션 코드의 별도 단계입니다.
        버튼을 눌러 필드가 채워지는 과정을 보세요.
