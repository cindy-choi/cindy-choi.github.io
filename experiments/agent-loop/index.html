A / REQUEST

요청은 먼저
harness가 받는다.

사용자가 주간보고를 요청합니다. harness는 모델 바깥에서 모델 호출과 도구 실행을 반복하는 프로그램입니다. harness가 요청을 받고 처리를 시작합니다. 아직 업무 데이터는 없습니다.

B / PREPARE

harness가
첫 context를 만든다.

harness는 system prompt, tool definitions, 보고 기간, skill catalog, 사용자 요청을 모읍니다. 이 묶음이 context입니다. context는 모델이 한 번의 호출에서 읽는 입력 전체입니다.

C / OUTPUT

모델은 보고서 대신
tool call을 출력한다.

업무 데이터가 없으므로 모델은 작성 절차부터 요청합니다. 모델의 출력은 tool call 또는 final response입니다. tool call은 도구 실행 요청이고, final response는 사용자에게 줄 답입니다. harness는 출력이 둘 중 무엇인지 확인합니다.

01 / DISCOVER

모델은 먼저
skill catalog를 받는다.

스킬은 작업 절차를 적은 파일입니다. skill catalog는 스킬의 이름과 설명 목록입니다. 이때는 파일 본문을 받지 않습니다.

02 / READ

harness가
파일을 읽는다.

모델은 read_skill tool call로 weekly-report 파일을 요청합니다. harness는 파일 본문을 읽어 tool result로 돌려줍니다.

03 / ASSEMBLE

모델은 본문을 보고
업무 조회를 요청한다.

harness는 tool result를 다음 호출의 context에 넣습니다. 모델은 이 context를 받아 다시 응답합니다. 이번에는 본문의 절차에 따라 업무 조회를 요청합니다.

04 / REVISE

v2에는
규칙 하나가 추가된다.

두 버전 모두 완료 업무 수집, 보고서 분류, 출처 연결을 수행합니다. 차이는 완료 후 다시 시작한 업무의 처리입니다.

v1 · 기존 파일
재개 업무의 처리 규칙 없음
v2 · 수정한 파일
+ 재개 업무는 진행 중으로 분류

왼쪽 파일은 v2로 수정했습니다. 오른쪽 context에는 아직 v1이 남아 있습니다.

05 / RELOAD

모델은 새 규칙에 따라
조회 조건을 바꾼다.

harness는 v2 본문을 다시 읽어 다음 호출의 context에 넣습니다. 모델은 새 규칙에 따라 status history도 요청합니다. status history는 업무 상태가 바뀐 이력입니다. 이전 context의 v1 본문은 그대로 남습니다.

context와 tool call

model call은 모델에 context를 보내 응답을 받는 한 번의 과정입니다. harness는 파일 본문을 tool result로 다음 context에 넣습니다. read_skill은 파일 읽기 tool call이고, search_work는 업무 조회 tool call입니다. include_status_history가 false이면 status history를 조회하지 않고, true이면 함께 조회합니다. 아래 데이터는 설명용 예시입니다. 실제 API 규격이 아니며, 실제 업무를 조회하지 않습니다.

D / EXECUTE
모델은 요청만 한다.
실행은 harness가 한다.
harness는 출력이 tool call인지 확인합니다. 허용된 도구인지와 인자를 검사합니다. 그다음 업무 데이터를 조회합니다. 모델은 아직 결과를 받지 않았습니다.

      
E / RECORD
tool result는
새 호출의 context로 들어간다.
harness는 tool call과 tool result를 history에 추가합니다. history는 지금까지 오간 요청, tool call, tool result의 목록입니다. model call ②는 이미 끝났고, 그 context도 바뀌지 않습니다. harness는 history를 넣어 model call ③을 새로 시작합니다.

      
F / DECIDE
빠진 정보가
다음 행동을 정한다.
조회 결과에 재개 사유와 다음 조치가 없습니다. 모델은 WORK-17의 상세 데이터를 요청합니다. harness는 같은 방법으로 검사하고 실행합니다.

      
G / REPEAT
같은 순서가
한 번 더 돈다.
harness는 상세 결과를 history에 추가하고 model call ④를 시작합니다. 첫 조회 결과는 그대로 남습니다. 이제 context에 보고서에 필요한 근거가 있습니다.

      
H / RESPOND
final response가 나오면
반복이 끝난다.
모델은 tool call 대신 보고서를 출력합니다. harness는 출력이 final response인지 확인합니다. harness는 보고서를 사용자에게 전달하고 실행을 끝냅니다. 보고서를 발송하지는 않습니다.

    

  


  

    
TRACE

    
model call 네 번.
tool call 세 번.

    
모델은 매번 다음 행동 하나를 출력합니다. harness는 출력이 tool call이면 도구를 실행하고 모델을 다시 호출합니다. final response이면 끝냅니다. trace는 이 과정을 순서대로 남긴 실행 로그입니다.
